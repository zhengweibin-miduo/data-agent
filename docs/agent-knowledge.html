架构总览

分层架构：上层依赖下层；编排层是唯一状态机，能力层被调用、彼此不直接耦合
⚠️
全局硬约束：模型输出 ≠ 可信事实（须过确定性校验）；MySQL 是权威源，ES/Qdrant 只是可重建投影；DDL 元数据的唯一提交出口是 persist_snapshot（accepted DDL snapshot 边界）。注：记忆 API、会话抽取、用户数据清除各有合法的独立权威写入事务，不受此出口约束。

编排 & 模型

编排层

LangGraph 工作流

workflow/graph.py · nodes.py · routing.py · state.py · contracts.py

职责：把「解析 → 分类 → 澄清 → 指标 → 校验 → 落库」编排成一个可中断、可续跑的状态机，是全项目唯一的控制流所在。

1StateGraph(DDLGraphState) · 图与节点
S

全流程有解析、LLM、校验、人工澄清等异构步骤，需要统一编排。

T

用一张有向图把 9 个步骤与分支连起来。

A

注册 9 个 async 节点 + 条件边，START→parse_ddl→…→persist_snapshot→END，每个节点只返回状态增量。

R

控制流集中在图里，步骤顺序与分支一目了然、可扩展。

2状态即事实 · DDLGraphState
S

任务可能中断、进程可能重启，状态必须能持久化恢复。

T

让整份状态可靠落盘并跨节点传递。

A

TypedDict(total=False) 只存 dict/list/str 等可 JSON 序列化值，落 Redis checkpoint，节点间不传对象引用。

R

任务可断点续跑，状态无隐藏可变对象，序列化安全。

3人在环中 · interrupt()
S

业务含义不足时必须等人工回答，期间不能产出错误结果。

T

在澄清点安全暂停并可恢复。

A

await_metric_answers 调 interrupt() 冻结 checkpoint，用 question_set_id 锚定回答契约，提交后 resume。

R

暂停期间图不前进、不落权威数据，澄清不污染结果。

4纯函数路由 · routing.py
S

业务判断与图结构耦合会让流程难懂难改。

T

把"下一步去哪"与节点逻辑解耦。

A

after_* 是纯函数，只读 state["route"] 返回下一节点名；route 只由刚跑完的节点写。

R

路由无副作用、易测试，所有失败分支统一指向 rejected → END。

5唯一成功出口 · persist_snapshot
S

多处写库会导致半成品和不一致。

T

把权威写入收敛到单一出口。

A

只有 persist_snapshot 能提交权威数据，build_memory_candidates 只构候选；_observed_node 给每个节点织日志边界。

R

写库路径唯一可控，业务代码里没有日志样板。

6有界修复预算 · *_attempts
S

模型可能反复产出坏结果，无限重试会卡死并烧钱。

T

给模型修复设一个硬上限。

A

semantic_attempts / metric_attempts 各 ≤1，存 checkpoint，结构化解析失败与确定性校验共享这一次预算。

R

再失败即转 DataAgentError 拒绝，杜绝无限重试。

7依赖注入 · DDLGraphDependencies
S

model/记忆/快照等依赖不可序列化，不该混进状态。

T

把进程内依赖与可持久化状态分开。

A

依赖经 contracts 注入 DDLWorkflowNodes，绑定在节点闭包里而不进 checkpoint。

R

checkpoint 保持纯数据，依赖可在恢复时重新注入。

工作流总览：主干（灰）＋修复回环（橙 ≤1）＋记忆跳过（绿）＋含义不足回问（蓝）＋拒绝出口（红虚线）
有界修复预算：解析与校验共享一次修复回环，耗尽即结构化拒绝
人在环中：interrupt 暂停 → 按 question_set_id 提交回答 → resume
模型接入

LangChain / LLM

workflow/llm_metadata_generator.py · infrastructure/llm_client.py

职责：把有界结构化输入交给模型，强制返回 Pydantic 契约，为编排层提供三类语义/指标生成能力；模型只补语义，绝不改结构。

1强制结构化输出 · with_structured_output
S

模型可能返回自由文本或幻造字段。

T

强制模型返回严格的 Pydantic 契约。

A

with_structured_output(output_type, method) 绑定类型，method 来自配置，禁止文本/宽松 JSON 降级。

R

"模型输出≠事实"的边界不被降级打破。

2可复现 + 并发预算
S

随机性影响可复现，并发会打爆端点。

T

稳定输出并限制并发。

A

temperature=0 + asyncio.Semaphore(max_concurrency)。

R

同输入尽量同结构，端点不被 worker 并行任务压垮。

3LLMClient 单例与密钥
S

密钥敏感，重复建客户端浪费且易泄漏。

T

统一、安全地管理模型客户端。

A

单例 initialize() 幂等创建 ChatOpenAI，密钥仅从 DATA_AGENT_LLM_API_KEY 读取、缺失即失败，close() 释放 HTTP client。

R

密钥不入配置/仓库，连接可控可关闭。

4启动能力探针 · check_structured_output_capability
S

端点可能"声称支持"结构化输出却不履约。

T

启动期就验证真实能力。

A

用 _CapabilityProbe(ok=true) 向真实端点发一次结构化请求，同时校验响应类型和值。

R

不合格端点启动即暴露，避免运行期降级。

5三类调用 · classify / plan / metrics
S

分类、澄清、指标是不同任务，不能一个提示打天下。

T

为每个阶段提供专用生成能力。

A

各有 system prompt 与有界 payload；plan_questions 带轮次与历史回答，generate_metrics 输出 missing_business_meaning。

R

每阶段职责清晰，缺口显式而非硬编。

6Prompt 硬约束
S

LLM 易臆造对象或引用不存在的 ID。

T

从提示层压住幻觉。

A

只允许用已给 table/column ID、必须引用回答 question ID、描述是已接受事实、每对象恰好一次、缺口显式列出。

R

模型只补语义、不改结构、不臆造。

7有界输入 + 二次确认
S

长 DDL 回灌模型浪费，且返回类型仍需保证。

T

精简输入并二次校验输出。

A

payload 紧凑 JSON 且 exclude canonical_ddl；返回后再 isinstance，TypeError/ValueError 交修复预算。

R

输入有界、输出类型可信，异常收敛到预算。

结构化输出调用：绑定契约 → 并发闸 → 端点 → 类型校验；失败进入节点修复预算（禁止文本降级）
确定性内核

DDL 解析 & 校验

ddl_metadata/parsing.py · validation.py · models/physical.py · identifiers.py

职责：唯一产生「可信事实」的地方。确定性地把 DDL 变成 PhysicalSchema，并对每一次模型输出做重新校验——模型结果必须回到这里被判定。

1确定性解析 · sqlglot
S

表/列身份必须绝对确定，不能受模型影响。

T

从 DDL 得到确定性物理结构。

A

parse_ddl 在线程外边界用 sqlglot 解析出 PhysicalSchema。

R

全流程唯一物理事实，模型只能补语义不能改结构。

2身份锚点 · 三种 fingerprint
S

记忆复用与快照版本要能精确对齐。

T

给版本与作用域一套稳定标识。

A

ddl_hash（整份）、schema_fingerprint（schema 级）、scope_fingerprint（单个表/列）。

R

指纹变即不兼容，复用/快照按锚点对齐。

3语义 / 问题校验
S

模型分类与问题可能引用不存在的对象。

T

校验模型输出是否与物理结构一致。

A

validate_metadata 逐项对照结构（存在性、主外键角色）；validate_metric_questions 校验问题引用。

R

无效分类/问题不能进入下一步或 interrupt。

4指标 finalize + 校验
S

模型指标是碎片，需与证据合成完整定义再判定。

T

把指标 finalize 并校验业务契约。

A

finalize_and_validate_metrics 合成后校验引用/表达式/契约，返回 (finalized, issues)。

R

只有 finalized 结果能进入记忆构建与落库。

5可修复判定 · ValidationIssue.repairable
S

有些校验问题可让模型改，有些不能。

T

决定是否值得回环重试。

A

只有"全部问题可修复且预算未耗尽"时才回环让模型修一次。

R

避免无意义重试，其余收敛为业务拒绝。

6核心不变量
S

模型输出天然不可信。

T

保证只有经校验的事实能推进。

A

任何模型结果都要重新过确定性校验；失败产出带 code/stage/retryable/details 的 DataAgentError。

R

结构永不被 LLM 改动，错误结构化可分类。

确定性内核：PhysicalSchema 是唯一事实源，三个校验器都以它为基准判定模型输出

记忆系统

记忆 · 领域

长期记忆 · Domain

memory/domain/{candidates,lifecycle,ranking,policies,payloads}.py · workflow/memory_context.py

职责：把「已接受结果」确定性地变成权威记忆候选，并管理其生命周期、冲突与投影文本——全部为纯函数式领域逻辑，不做 I/O。

1候选构建 · build_accepted_memories
S

已接受结果要变成可复用、可追溯的记忆。

T

确定性地构建权威候选。

A

由 Schema/语义/问答/指标 + 兼容记忆产出 MemoryCandidate，附 uid/指纹/trust/版本/job_id。

R

候选带完整来源，可追溯到证据。

2生命周期裁决 · decide_memory
S

写入会遇到删除、空槽、同内容、合并等情况。

T

确定性决定对记忆做什么。

A

按固定顺序返回 ADD/UPDATE/MERGE/DELETE/NOOP，先处理删除与空槽，再用 same_content 拦幂等。

R

避免墓碑，防止同内容被当新版本累积。

3语义等价 · semantically_equivalent
S

同一事实可能因表述不同被当成新内容。

T

按含义而非文字判等价。

A

按值比较；UserMemoryContent 只比归一化后的 value（大小写/空白折叠）。

R

同一事实不因描述差异反复更新。

4类别策略 · MemoryCategoryPolicy
S

不同记忆类别的写入/检索规则不同。

T

用策略统一驱动行为。

A

每类声明 schema、生命周期、importance、retrieval_weight、content_types、user_scoped、conflict_strategy(replace/merge)。

R

写入与检索由策略统一，不散落硬编。

5排名融合 · RRF
S

ES 与 Qdrant 分数量纲不同，无法直接比较。

T

融合两种排名成统一序。

A

reciprocal_rank_fusion 用 1/(constant+rank) 融合，精确命中 +1.0，按 (-score,uid) 稳定排序。

R

结果确定可复现，并列有稳定 tie-break。

6投影转换 · payloads
S

记忆要能做稳定哈希与检索文本。

T

从权威内容生成稳定投影。

A

canonical_content_json（排序去空白 exclude_none）、memory_content_hash(SHA-256)、build_memory_text(≤2048)。

R

内容可回查、可检索，哈希稳定。

7加载与裁决 · MemoryContextLoader
S

兼容记忆可能陈旧或冲突，且不能凌驾当前 DDL。

T

安全复用兼容记忆。

A

按 scope_fingerprint 取记忆、content_hash 剔陈旧、user_confirmed 优先、冲突抛 memory_conflict，最后过当前 AST validate_metadata。

R

复用内容仍要 AST 裁决，冲突显式不静默。

decide_memory 决策流程：确定性 if-cascade，先裁决删除/空槽/幂等，再按 merge 意图决定 MERGE 或 UPDATE，避免墓碑或同内容被误判为新版本
记忆 · 应用

记忆检索 · Application

memory/application/{search,service}.py

职责：对外提供 Mem0 风格的记忆读写用例，内部做混合检索 + MySQL 权威回查，保证返回的永远是当前有效的权威内容。

1混合检索 · MemorySearchService
S

单一召回方式会漏检。

T

用两条通路互补召回。

A

并发查 ES(全文) 与 Qdrant(向量，先 TEI 嵌入)，RRF 融合。

R

召回更全，漏检被另一路补上。

2权威回查
S

外部索引可能陈旧/损坏。

T

保证返回的是当前有效权威内容。

A

检索只给 UID，内容从 MySQL 取回并用 memory_content_hash 与 content_hash 比对，不一致丢弃。

R

绝不把陈旧投影当事实返回。

3范围限定
S

混合检索可能引入无关记忆。

T

限制检索范围。

A

allowed_object_ids / categories 限范围，混合检索只补精确查询的空槽。

R

只补空槽、不取代精确查询，结果相关。

4写入用例 · MemoryService
S

记忆写入需要一致的策略与去重。

T

提供领域安全的写 API。

A

add/update/delete 按 category_policy 应用冲突与生命周期策略。

R

对外简单，对内每次写入都经策略去重。

5投影异步对齐
S

外部索引可用性不该阻塞读写。

T

解耦权威写入与投影同步。

A

写权威表时只登记 outbox 期望状态（同事务），实际更新交 dispatcher 异步幂等。

R

读写不被索引可用性阻塞，最终一致。

混合检索：ES + Qdrant 并发出候选 → RRF 融合 → 只拿 UID 回 MySQL 取权威内容并 hash 核对
记忆 · 投影

记忆投影 · Indexing

memory/indexing/{dispatcher,elasticsearch,qdrant,rebuilder}.py

职责：把 MySQL 权威记忆异步、幂等地投影到 ES / Qdrant。投影可随时从权威源重建，本身不是事实来源。

1批量领取 · Dispatcher.dispatch
S

outbox 可能积压，需要有界处理。

T

按批可靠地推进投影。

A

事务内 claim_outbox 一批（上限 batch_size），逐项处理，成功才 acknowledge。

R

有界批处理，成功才确认。

2两目标独立确认
S

ES 与 Qdrant 可能一个成功一个失败。

T

保证两目标都真正落地。

A

两者各成一条期望状态，各自 upsert/delete、各自 ack，互不替代。

R

避免"半同步"被当成完成。

3从权威源重建
S

直接搬旧内容可能写出过期快照。

T

保证投影等于权威当前值。

A

每次用 memory_uid 回 MySQL 取当前 projection 再写索引。

R

重复投递幂等，不写过期内容。

4TEI 嵌入
S

向量检索需要嵌入。

T

为 Qdrant 生成向量。

A

写 Qdrant 前 aembed_documents(memory_text)，向量与 payload 一起 upsert。

R

向量投影与全文投影各就各位。

5失败隔离与退避 · retry_outbox
S

单点失败不该拖垮整批。

T

隔离并重试失败项。

A

单目标失败只退避该行（记录异常、按 max_backoff），保留期望状态。

R

不阻塞其它项、不回滚已成功目标。

6全量重建 · rebuilder
S

灾难或版本升级需要重建投影。

T

从权威源整体重建。

A

rebuilder 从 MySQL 重建整套 ES/Qdrant 投影。

R

投影可丢可重建，非事实源。

投影分发：从 outbox 领取期望状态，逐项从 MySQL 重建后幂等写 ES / Qdrant，两目标独立确认，失败仅退避自身行
记忆 · 存储

记忆存储 · MySQL

memory/mysql/{repository,index_outbox,tables}.py

职责：长期记忆的权威关系存储与 outbox 表，是所有记忆读写和投影重建的唯一事实来源。

1仓库查询 · MemoryRepository
S

需要按作用域找当前有效记忆。

T

提供按指纹/版本的查询。

A

find_compatible_scopes（source+指纹+类别+content_version）、find_active_by_fingerprint。

R

查询即"按作用域取当前有效版本"。

2StoredMemory
S

上层要判断内容是否被破坏、谁更可信。

T

承载权威内容与元信息。

A

权威内容 + 明细（content_hash、trust、生命周期状态）。

R

支撑 hash 回查与 user_confirmed 优先。

3事务性 outbox · MemoryIndexOutboxRepository
S

权威写入与投影同步要可靠解耦。

T

把投影同步做成可靠消息。

A

claim / acknowledge / retry / projection 四个操作。

R

可重试的消息流，权威与投影解耦。

4表定义 · tables.py
S

项目不用 ORM/迁移框架。

T

用显式方式定义表。

A

SQLAlchemy Core 声明记忆/明细/outbox 三类表，配 bootstrap SQL。

R

无 ORM 实体层，读写用显式 SQL。

5版本隔离
S

升级时新旧内容不能互相误判。

T

隔离内容/投影版本。

A

content_version / projection_version 参与查询与哈希。

R

旧版本不被误判兼容，可平滑并存升级。

记忆 · 会话

会话记忆 · Conversation

conversation/{service,extraction,repository,models,mysql_tables,api}.py

职责：管理永久、用户拥有的文本轮次，提供有界上下文，并异步从对话中提炼可复用的用户记忆。

1幂等轮次 · ConversationService
S

客户端重试不能产生重复轮次。

T

提供永久、幂等的轮次。

A

start/complete turn 用稳定标识，会话与消息可分页。

R

重复提交不产生重复轮次。

2有界上下文召回
S

上下文不能跨用户串味。

T

只取同用户相关记忆。

A

复用 MemorySearchService，按 CONVERSATION_MEMORY_SOURCE 与用户作用域隔离。

R

数据面杜绝跨租户/用户泄漏。

3异步抽取 · extraction
S

对话里有可复用的用户事实。

T

提炼有证据的用户记忆。

A

4数据所有权 · 两种删除粒度
S

T

A
