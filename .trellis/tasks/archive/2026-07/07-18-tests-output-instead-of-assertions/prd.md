# 将所有测试改为输出结果

## Goal

让 `tests/` 目录中的全部测试既能输出实际结果供人工观察，又能保留自动判定能力，在结果不符合预期时阻止回归。

## Background

- 当前 `tests/` 下共有 14 个包含断言的测试文件。
- 当前共发现 228 处 Python `assert`。
- 测试同时覆盖普通结果比较、对象身份与类型、集合关系、异步调用、外部基础设施，以及预期异常分支。
- 测试继续由 pytest 收集和运行，并保留自动失败语义。
- 仓库已有 `tests/helpers/` 测试辅助模块，可承载统一的输出与检查函数。
- pytest 默认捕获标准输出；人工实时观察时使用 `uv run pytest -s`，日常自动验证仍使用默认捕获模式。

## Requirements

- 修改范围覆盖 `tests/` 下所有现有测试文件。
- 将普通 `assert` 改为统一的“输出后检查”调用，输出应包含场景标签、实际值、期望值和 PASS/FAIL 状态。
- 输出完成后仍须执行自动检查；不匹配时通过 `pytest.fail()` 让 pytest 失败。
- 异步调用不能因移除 `assert` 而被跳过；原断言表达式中的调用必须继续执行并输出结果。
- 保留资源创建、清理、连接关闭和 fixture 生命周期。
- 预期异常分支应输出捕获到的异常类型和关键信息，并继续检查异常是否符合预期。
- 原本用于表示“预期异常未发生”的显式失败分支改用统一失败辅助函数；仅用于注入运行故障的异常不改变行为语义。
- 不修改 `pyproject.toml` 的默认 pytest 捕获配置。
- 不修改 `src/` 中的生产代码。

## Acceptance Criteria

- [x] 所有原有检查点都具有可人工阅读的输出。
- [x] 检查不匹配时 pytest 仍会失败并显示对应场景。
- [x] `tests/` 下不再存在裸 Python `assert` 语句。
- [x] 原断言表达式中的函数调用、异步调用和属性读取仍会执行。
- [x] 每项输出包含足以识别测试场景和结果的标签。
- [x] 预期异常场景采用统一且可读的输出格式。
- [x] `uv run pytest -s -m "not integration"` 能实时显示检查输出。
- [x] Ruff、Pyright 与 pytest 收集检查通过。

## Out of Scope

- 修改生产代码行为。
- 新增业务功能。
- 调整外部基础设施配置。
