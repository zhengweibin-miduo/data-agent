# 测试输出与自动回归检查设计

## 设计目标

在不削弱 pytest 自动回归能力的前提下，让每个现有测试检查点都输出可供人工阅读的结果，并移除测试文件中的裸 `assert` 语句。

## 边界

- 改动仅限 `tests/`。
- 不改变 `src/data_agent/` 的生产行为。
- 不改变 pytest 的默认输出捕获配置。
- 不增加第三方依赖。
- 不改变单元测试与集成测试的 marker、fixture、事务或资源清理边界。

## 核心方案

在 `tests/helpers/checks.py` 提供统一检查能力：

1. 相等性检查接收场景标签、实际值和期望值。
2. 条件检查接收场景标签、判断结果、实际值和人类可读的期望描述。
3. 显式失败函数用于“预期异常未发生”等无法形成普通比较结果的场景。
4. 每次检查先以统一格式输出：

   ```text
   [PASS] <场景> | actual=<实际值> | expected=<期望值>
   [FAIL] <场景> | actual=<实际值> | expected=<期望值>
   ```

5. 检查失败时调用 `pytest.fail(..., pytrace=False)`，让 pytest 返回失败并阻止回归。

辅助函数使用中文 Google Style Docstring，并从 `tests.helpers.checks` 显式导入，不通过 `tests/helpers/__init__.py` 聚合导出，避免无关包级副作用。

## 转换规则

### 相等与不等

- `assert actual == expected` 转为相等性检查。
- `assert actual != expected` 转为条件检查，输出实际值和“不等于 expected”的期望描述。

### 布尔、None、身份、类型与包含关系

- `assert value`、`assert not value`、`is None`、`is not None`、`is`、`is not`、`isinstance`、包含关系、集合关系和大小比较转为条件检查。
- 输出实际对象或派生出的可读值，以及对应期望描述。

### 复合表达式

- 能安全拆分的复合表达式拆为多个有标签的检查，提高可观察性。
- 拆分不得重复执行有副作用的调用。
- 不能拆分时先计算一次条件结果，再交给条件检查。

### 异步与有副作用调用

- `assert await call()` 改为先 `await` 一次并保存结果，再执行输出检查。
- 任何原断言中的函数调用只执行一次，避免重复写入、状态迁移或网络请求。

### 预期异常

- 捕获到预期异常后，输出异常类型和关键信息，并检查错误码或消息。
- 预期异常没有发生时，调用统一显式失败函数。
- 用于故障注入的异常类型保留原有控制流语义，不因机械替换而改变被测路径。

## 运行方式

- 自动回归：`uv run pytest ...`，输出由 pytest 捕获，失败时展示。
- 人工观察：`uv run pytest -s ...`，实时展示所有 PASS/FAIL 输出。
- 不把 `-s` 写入 `pyproject.toml`，避免 CI 和日常测试日志永久膨胀。

## 风险与控制

- 风险：机械转换导致表达式执行两次。控制：复杂或异步表达式先保存实际值。
- 风险：复合断言拆分后改变短路行为。控制：涉及属性访问或副作用时保留原求值顺序。
- 风险：`pytest.fail()` 被业务代码的 `except Exception` 捕获。控制：失败调用放在测试控制流外层或专用失败分支，并通过失败冒烟验证确认传播。
- 风险：输出不可读或过长。控制：使用明确场景标签和 `repr` 风格值；不输出密钥等敏感配置。
- 回滚：删除检查辅助模块并恢复对应测试调用；生产代码和配置不受影响。
