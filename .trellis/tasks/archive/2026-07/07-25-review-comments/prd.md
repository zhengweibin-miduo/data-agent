# 审查项目注释与备注

## Goal

核验当前项目中的注释、Docstring、待办标记和维护性备注是否准确、有效且符合仓库规范，并为核心业务流程补充能够解释步骤目的、顺序约束和设计原因的中文注释，使维护者无需反向推导整条控制流即可理解关键代码。

## Background

- 当前基线为 `origin/master` 的 `524f508`，审查工作在隔离分支 `chore/review-comments-20260725` 中进行。
- `src/` 有 85 个 Python 文件、约 520 处 Docstring 和 2 处普通行注释；`tests/` 有 47 个 Python 文件、约 252 处 Docstring，未发现普通行注释。
- 生产源码和测试未发现 `TODO/FIXME/NOTE/HACK/XXX` 待办标记。
- 维护性备注主要位于 `pyproject.toml`、`.github/workflows/ci.yml`、Docker Compose 和 SQL schema `COMMENT`。
- `.trellis/spec/backend/quality-guidelines.md` 要求中文 Google Style Docstring，且复杂对象应说明非显然参数、结果、异常、副作用、事务、并发和生命周期约束。
- `code_review.md` 要求审查结论使用简体中文、保留英文技术事实，并为每条确认问题提供准确的 `文件路径:行号`、触发条件和可观察后果。
- 现有 Python 代码共有 772 个 Docstring，但 `src/` 只有 2 条普通行注释；大量符号说明了“做什么”，没有解释复杂流程“为什么按这个顺序做”。
- 用户明确要求在核心流程中补充步骤和原因注释，并同意避免逐行翻译式注释。

## Requirements

- **R1 审查范围**：检查 `src/**/*.py`、`tests/**/*.py`、`pyproject.toml`、`.github/workflows/ci.yml`、`conf/**`、根级现行说明文件以及 `docs/docker/**` 中的人工注释、Docstring 和维护性备注。
- **R2 Docstring 语义**：核对 Docstring 与函数签名、实现、调用方和测试的一致性，重点检查错误的参数/返回值/异常说明，以及遗漏或误述的事务、并发、副作用和生命周期约束。
- **R3 注释价值**：识别复述可见代码、机械占位、历史变更叙述、注释掉的代码、不可执行待办和缺少理由的工具抑制；合理的 rationale、invariant 和必要 `noqa` 不得误报。
- **R4 维护备注有效性**：核验依赖兼容、CI action 版本、运行配置等备注是否仍与当前配置和可验证事实一致；无法离线确认的外部事实必须标为“待外部核验”，不得猜测。
- **R5 SQL 契约**：把 SQL `COMMENT` 作为 schema 业务契约，与模型、仓储和配置字段语义核对，不按普通注释措辞问题处理。
- **R6 报告证据**：每条确认问题只描述一个根因，提供严重程度、准确 `文件路径:行号`、相关实现/调用/测试证据、影响和最小修复建议；同一根因的多处影响合并报告。
- **R6.1 分层口径**：最终报告先列符合 `code_review.md` 定义的 `P0/P1` 阻塞问题，再单列已核验的非阻塞维护问题；维护问题不得伪装或升级为阻塞问题。
- **R7 验证透明度**：记录实际执行的扫描、Ruff 和其他验证；未执行或受环境限制的检查必须明确说明。
- **R8 有限修改**：允许修改核心业务流程源码中的注释和 Docstring，不改变运行时语句、控制流、数据结构、配置或测试行为。
- **R9 核心流程可读性**：优先覆盖 DDL 任务/工作流、conversation 生命周期、长期记忆更新与检索流程，解释关键步骤的目的、顺序、事务/租约边界、outbox/checkpoint、重试恢复和业务不变量。
- **R10 注释质量**：新增注释使用简体中文，保留英文标识符和协议术语；只解释无法从语句直接看出的 rationale、invariant、边界或阶段转换，禁止把每行代码翻译成中文。
- **R11 准确性保护**：新增或修改的注释必须与当前签名、实现、直接调用方和测试一致；修复审查报告中已确认的 4 个非阻塞维护问题。

## Acceptance Criteria

- [x] 所有 R1 范围均已纳入清单，并明确列出排除项。
- [x] Python Docstring 已按模块分区完成语义审查，而不是只依赖 Ruff 或关键字检索。
- [x] 普通注释、工具抑制和待办标记已完成全范围字面扫描及人工核验。
- [x] 配置/CI 维护备注与 SQL `COMMENT` 已按 R4、R5 的不同标准核验。
- [x] 每条报告问题都能由准确行号和相关代码证据复核；无法确认的候选项未作为缺陷发布。
- [x] `P0/P1` 与非阻塞维护问题分区展示，严重程度和措辞不会造成混淆。
- [x] 报告单列已执行验证、未执行验证、排除范围和剩余风险。
- [x] DDL、conversation 和长期记忆三条核心流程均有经过核验的关键步骤/原因注释。
- [x] 新增注释不复述可见代码，不引入新的过期承诺、错误异常说明或错误生命周期描述。
- [x] 已确认的 4 个非阻塞维护问题全部修复，并有定点验证证据。
- [x] 产品 diff 仅包含注释、Docstring 或维护备注，不改变 Python AST 中的可执行结构。
- [x] Ruff、Pyright、相关单元测试和注释专项检查通过。

## Out of Scope

- `.trellis/workspace/**`、`.trellis/tasks/archive/**`、`.trellis/worktrees/**` 中的历史过程记录。
- `.agents/skills/**`、`.codex/**` 等工具或平台内容。
- `uv.lock`、模板哈希、缓存、构建产物和第三方生成文件。
- 为简单 getter、字段赋值、明显 CRUD 或测试准备步骤添加逐行解释。
- 重构实现、改变业务行为、修改测试断言、推送分支或创建 Pull Request。
