# 设计 Data Agent 前端产品方案

## Goal

为当前只有后端能力的 Data Agent 定义一套可落地的前端产品方案。首版聚焦为“带 AI 协作的 DDL 语义化工作台”：帮助数据工程师或分析工程师提交 MySQL DDL、理解异步处理进度、与 LLM 对话补充业务语义、完成必要的指标澄清，并查看生成结果摘要与修正可复用知识。

首版必须忠于现有 API。AI 聊天是确认的产品需求，但当前后端只具备会话持久化而没有 LLM 编排端点，因此方案必须显式包含这个最小后端依赖，不能用前端直连模型或静态回复伪装完成。

## Confirmed Facts

- 产品主题是 MySQL DDL 到语义元数据与指标的异步生成，不是通用聊天机器人。
- 后端已完整支持 DDL 任务提交、状态查询、可重连 SSE 进度、澄清回答与结果摘要。
- 后端已支持按数据来源搜索、查看、修正、查看历史和软删除元数据记忆。
- 会话接口只持久化用户/助手消息；没有调用 Agent、LLM 或流式返回助手答案的 HTTP 接口。
- 现有会话服务已能组装摘要、近期消息和用户长期记忆，并在助手消息完成后触发异步记忆提炼，可作为聊天编排的上下文与持久化基础。
- 当前没有前端框架、前端工程、认证与权限系统、任务列表接口或元数据快照详情查询接口。
- API 仅面向本地回环地址部署，首版不能宣称公网 SaaS 或多租户产品。

## Confirmed Product Decision

- 主要受众：维护数据仓库语义口径的数据工程师 / 分析工程师；用户已确认。
- 单一核心任务：把一份 MySQL DDL 可靠地推进到“语义元数据已生成”，中间只在系统确实需要时回答澄清问题。
- 产品形态：本地单用户工具；任务工作台为主，知识记忆为辅助。
- AI 聊天边界：首版只围绕当前数据来源和 DDL，补充业务语义、解释结构并辅助起草澄清答案；用户已确认。不支持脱离 DDL 的自然语言数据问答。

## Visual Revision

- 用户已否决第一版浅色 Blueprint 宣传页式视觉；功能范围保持不变，视觉实现必须重新设计并再次确认。
- 新方向必须让 DDL 编辑器、Schema Trace 和 AI 协作在首屏形成真正的工程工作台，禁止巨型营销标题挤压任务空间。
- 用户已选择“可视化数据画布”方向：画布必须基于后端确定性 DDL 解析返回的真实表、字段和关系，不在浏览器重复实现 SQL 解析。
- 用户已确认 Semantic Night Canvas 的真实节点与外键截图，视觉方案通过。

## Requirements

### MVP

- R1. 提供 DDL 工作台，采集 `source`、固定 `mysql` 方言和 DDL 文本，并在提交前展示现有大小/命名约束。
- R2. `202 Accepted` 只能显示“已受理”，不能显示“已开始”或“已完成”。
- R3. 使用 SSE 作为主进度通道，并提供断线后状态查询回退；界面只展示公开业务阶段。
- R4. 当状态为 `waiting_input` 时，在任务上下文内逐项呈现问题、关联事实表/列及必填标识，提交时携带当前 `revision` 与 `question_set_id`。
- R5. 终态明确区分 `succeeded`、`rejected`、`failed`，成功页只展示 API 实际返回的表/列/指标数量和 DDL 哈希。
- R6. 提供知识记忆搜索与详情：以 `source + query` 为入口，支持查看版本历史、带版本号修正和软删除确认。
- R7. 所有错误状态使用稳定的 `code`、`stage`、`retryable` 决定文案和操作，不暴露内部 LangGraph/控制面细节。
- R8. 保持本地单用户假设；`source` 是数据来源标识，不包装成已认证的租户或账号。
- R9. 首版键盘可完成主流程，焦点清晰，状态不只依赖颜色，动效尊重 `prefers-reduced-motion`。
- R10. AI 聊天必须允许用户围绕当前数据来源和 DDL 补充业务背景、解释术语并帮助形成澄清答案；聊天上下文复用现有会话摘要、近期消息和用户长期记忆。
- R11. 新增后端聊天编排契约，服务端完成 `start_turn → LLM 调用 → complete_turn`；前端不得持有模型密钥或直接调用模型端点。
- R12. 普通聊天与 DDL 结构化澄清保持边界：AI 可以起草答案，但只有用户明确确认后，才调用 DDL job 的 answers API。
- R13. 涉及数据问答时必须经过 answer-readiness；数据未就绪只展示安全固定文案，不泄漏内部同步状态。
- R14. 新增只读 DDL preview 契约，复用现有 MySQL DDL 解析器输出画布需要的表、字段与外键关系；preview 不创建任务、不调用 LLM、不持久化。
- R15. 前端主界面改为全屏数据画布：DDL/结构导航、真实 schema 节点、AI 协作和 Schema Trace 同屏，不出现营销 hero。

### Explicitly Out of Scope

- 与当前数据源无关的通用 AI 助手；首版聊天必须服务于 Data Agent 的语义补充或数据问答目标。
- 登录、角色权限、多租户隔离、Agent 注册、附件与多模态。
- 服务端任务历史列表；现有 API 只能按已知 `job_id` 查询。
- 元数据表/列/指标完整详情浏览与编辑；现有任务结果只返回数量摘要。
- 公网 SaaS、移动端原生应用、运营 Dashboard、通知中心和主题系统。
