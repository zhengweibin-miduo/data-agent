# 让 LLM 通过工具检查数据同步就绪状态

## Goal

在回答用户问题前增加独立的意图识别步骤，判断该问题是否必须等待相关
DW 表同步完成。确定性路由只在识别结果要求等待时，通过受控 Tool Calling
检查内部数据就绪状态；同步进度和控制面细节不向用户暴露。LLM 不直接生成
状态 SQL，也不新增公开 HTTP 查询接口。

## Background

- 当前仓库只有结构化 LLM 调用，没有现成的 tool registry、`bind_tools`
  或通用 agent runner。
- 数据同步能力正在独立任务
  `07-27-sync-conversation-metadata-dw` 中实现，任务状态位于独立
  `data_sync.data_sync_task`，该任务的代码尚未提交。
- 同步任务可通过来源、源 schema、源表和目标表唯一定位；当前模型没有
  `user_id` 或会话归属字段。
- 可用阶段包括结构准备、记录基线、历史回填、事件追平、实时同步、暂停、
  冲突和死信。

## Requirements

- 使用 LLM Tool Calling 执行内部 readiness check，而不是让 LLM 访问数据库、
  拼接 SQL 或调用新增
  的公开 HTTP API。
- 在正常回答之前执行一个独立、类型化的意图识别节点，至少输出
  `requires_sync_completion`，不得把该判断隐含在自由文本回答或工具选择中。
- 确定性工作流根据意图识别结果路由：
  `false` 直接进入正常回答；`true` 进入同步状态检查，再决定回答或返回
  未就绪状态。
- 意图识别同时给出回答所依赖的 DW 目标表；不依赖 DW 数据的问题不得因
  同步状态而阻塞。
- 当识别结果依赖一个或多个 DW 表的数据完整性时，工作流必须调用状态
  工具，并把所有依赖表的状态作为是否继续回答的门禁。
- 多来源共同写入同一目标表时：问题明确限定来源则只检查该来源；问题未
  限定来源或属于汇总查询时，必须检查该目标表的全部有效来源。
- 意图识别失败、结果缺字段或声称需要等待但没有依赖表时，不得默认继续
  查询并生成可能不完整的业务答案。
- 意图识别结果首次不满足类型或业务约束时，允许一次结构化修复；修复仍
  失败时安全拒答，并提示用户重新表述，不查询或使用可能不完整的 DW 数据。
- 只有所有必需表均处于可回答状态时，LLM 才能基于 DW 数据回答；不得在
  未就绪状态下把不完整数据描述为完整结果。
- 可回答状态严格定义为所有必需同步任务均处于 `streaming`。任一任务尚未
  就绪时，当前请求立即返回统一的稍后重试提示，不在请求内轮询。
- 未就绪时面向用户只返回固定提示“数据准备中，请稍后重试”，不得附带
  内部表、来源或状态信息。
- 新增只读状态查询边界；不得复用会领取租约或改变任务状态的方法。
- 工具按稳定业务身份查询，不要求 LLM 知道 `data_sync_task.id`。
- 工具输出必须有界、类型化，并以 `ready` 作为确定性路由依据。内部可以
  保留阻塞任务身份和状态码用于日志与诊断，但不得进入面向用户的回答内容。
- 不向用户输出来源同步明细、阶段、重试次数、错误类型、时间、回填游标或
  Binlog 位点。
- 不得输出源连接 URL/账号/密码、租约令牌、`desired_json`、业务行、
  Binlog 事件载荷或原始异常内容。
- 不计算或展示同步百分比。
- 保持现有对话、DDL Job 与 Meta 快照接口语义不变。
- 直接复用依赖任务最终落地的 `data_sync` 模型与 repository，不复制第二套
  同步状态模型。

## Acceptance Criteria

- [ ] LLM 能通过一个明确命名的工具检查指定问题所需 DW 数据是否就绪。
- [ ] LLM 能区分“不依赖 DW 同步的问题”和“必须等待指定 DW 表同步完成
  才能回答的问题”。
- [ ] 意图识别是正常回答前的独立工作流节点，输出通过类型化模型校验并由
  确定性条件边路由。
- [ ] 无效意图结果最多修复一次；持续无效时不进入业务回答路径。
- [ ] 多表问题会检查全部依赖表，任一必需表未就绪时不会给出伪完整答案。
- [ ] 来源限定问题只检查指定来源；未限定来源的汇总问题检查目标表全部
  有效来源。
- [ ] 必需任务未进入 `streaming` 时立即返回统一提示，不启动请求内轮询。
- [ ] 未就绪响应固定为“数据准备中，请稍后重试”，不包含内部状态明细。
- [ ] 工具查询是只读的，不领取或续租同步任务，不推进阶段、位点或重试。
- [ ] 查询结果把所有内部同步阶段稳定归并为 `ready` 或 `not_ready`，不向
  用户投影具体进度。
- [ ] 未找到任务、身份不完整或匹配不唯一时返回 `not_ready`，不泄露内部
  控制状态。
- [ ] 工具参数和结果不包含凭证、租约、业务行或 Binlog 事件载荷。
- [ ] LLM 回答不包含同步阶段、位点、重试、冲突或死信明细。
- [ ] 本任务不接入 `ConversationService`、HTTP 路由或任何实际用户回答链路；
  仅交付供后续入口调用的内部能力。
- [ ] 单元测试覆盖工具 schema、就绪映射、无任务和敏感字段排除。
- [ ] 集成测试证明查询真实 `data_sync` 状态且不会修改任务记录。

## Out of Scope

- 面向前端、外部系统或运维平台的公开同步状态 API。
- 面向用户的同步进度、阶段、位点、冲突或死信信息。
- 通用 LLM 业务问答入口、`ConversationService` 接入、对话 API 或 agent
  runner。
- 同步任务暂停、恢复、重试或冲突处理工具。
- 估算源表总行数或承诺精确同步百分比。
- 在本任务中复制或重写尚未提交的 `data_sync` 实现。

## Dependency

- 实现必须基于 `07-27-sync-conversation-metadata-dw` 的最终提交或明确的
  堆叠分支；在依赖代码未进入本任务基线前，本任务只完成规划，不创建重复
  占位模块。
