# 将值索引简化为 V1 并修复投影与长文本读取

## Goal

在项目尚未投入使用、无需保留旧数据的前提下，将元数据字段值索引契约收敛为首个正式版本 V1，并修复 PR #71 中两个仍未解决的 P1 问题：共享目标表同名字段的逐来源投影缺失，以及长文本值在进入字节门禁前被无界读入内存。

## Background

- PR #71 当前未解决问题位于 `projections.py:111` 和 `value_refresh.py:423` 附近。
- 用户确认当前没有需要保留的数据库、Elasticsearch、Qdrant 或其他历史索引数据。
- 本轮不设计旧版本升级、回退、清理或兼容迁移；只有用户未来明确要求迁移数据时才进入迁移设计。

## Requirements

- R1：多个物理来源映射到同一目标表且存在同名合格字段时，每个逻辑 `(table_id, column_id)` 都必须保留独立的值索引投影，不得因字段名重复而整体排除。
- R2：投影归属必须基于现有可验证的来源、目标表和字段契约；不得通过猜测共享 DW 行的字段来源制造错误归属。
- R3：SCAN 与 SELECT_TOP_N 读取文本值时必须在数据库读取边界受到字节预算约束，不能先 `.all()` 读入最多 1,000/10,000 个完整 LONGTEXT 后再判断大小。
- R4：超长单值必须有明确、可恢复的处理结果；任务不能无限重试同一值，也不能通过静默截断改变可检索语义。
- R5：`llm`、长期记忆和元数据索引的项目协议/内容/投影版本统一为首个正式版本 `v1`；游标协议保持 `v: 1`；删除仅服务于不存在旧环境的 SQL 升级脚本。内容哈希、`desired_version`、`frequency_version`、`index_generation` 和正常的旧刷新代次回收不是历史版本迁移，必须保留。
- R6：保留现有短事务、持久化进度、租约/CAS、稳定文档 ID 和可重放远端操作约束。
- R7：不执行旧数据迁移；经用户明确授权，仅删除并重新初始化本地 5 个项目数据库。不得删除 MySQL 容器、Docker volume、系统库、向量索引或远端数据。

## Acceptance Criteria

- [x] 两个或以上来源的同名合格字段均能生成各自的值索引候选，文档身份仍区分 `table_id` 与 `column_id`。
- [x] 无法证明字段归属的共享 DW 数据不会被错误复制到多个逻辑字段；实现和测试明确归属边界。
- [x] SCAN 和 SELECT_TOP_N 的单次数据库结果在条数与估算/实际字节两方面均有界，长文本测试证明不会先构造无界 Python 列表。
- [x] 单值超过预算时任务以可观察、可恢复且最终收敛的方式处理。
- [x] `llm.graph_version`、全部 `memory.*_version`、`metadata_index.projection_version` 和相关当前规范统一为 `v1`；旧环境升级 SQL 已移除，当前 bootstrap SQL 与 SQLAlchemy Core 表定义保持一致。
- [x] 元数据值索引相关单元测试与集成测试通过；Ruff、Pyright、compileall 和配置加载检查通过。
- [x] 未执行旧数据迁移；仅按用户明确授权重建本地项目库，MySQL 容器、Docker volume、系统库、向量索引及远端 PR thread 状态均未触碰。

## Out of Scope

- 迁移、保留或转换任何既有数据。
- 回复或 resolve GitHub review thread、提交、推送或合并 PR；除非用户后续明确授权。
- 与上述两个 P1 问题及 V1 收敛无关的功能扩展。
